# Prepared execution boundary

Tool builders validate and bind arguments and evaluate their typed policy before calling the execution profile. The profile receives a defensive snapshot and a handler continuation. Cache lookup, approval and operation claim happen at this boundary; no profile may replay data before current authorization. Registry authorizer/policy and Session RunPolicy remain outside and run on every call.

The handler continuation uses the bound arguments captured by the builder, not arguments edited by a profile. Policy wrappers delegate to the innermost prepared boundary. Each binder runs once; wrapper validators and policies evaluate the final handler argument snapshot before the profile, including on replay and without a profile. Where argument types differ, the wrapper validates/decodes final canonical JSON into its own declared type; it does not authorize an earlier intermediate action. Opaque proof fields must be present in the final typed value if a policy needs them. Custom tools without a prepared boundary are rejected when registering a protected profile or constructing a policy wrapper. Profiles do not authenticate domain subjects or implement a scheduler.

A wrapper applies current delivery class and metadata to fresh captured outcomes and stored replay. Replay audience is never broadened: differing stored/current audiences intersect conservatively at internal-only delivery, including model versus user targets. Changing a wrapper cannot make an old internal outcome model-facing.

`toolsy.replay_source` is library-owned replay provenance, not wrapper configuration. Policy constructors reject this key in `EnvelopeMetadata`, regardless of its value. Runtime metadata overlays must also preserve the original replay source: repeated or nested transforms cannot turn a replay into a fresh outcome. Its string value is `result_cache` or `completed_operation`. Host reducers apply effects only on fresh outcomes, never on either replay source. Metadata is provenance from a trusted execution profile, not authorization or authenticity of arbitrary custom tools.

Snapshots preserve host-owned Go types rather than JSON-round-tripping typed values. Exported struct fields, pointer/map/slice/array data and cycles are defensively copied. Opaque private state, channel/function values and pointer-key identity are host-owned: hosts must keep those immutable for the invocation and supply trusted opaque binding for state affecting authorization/action. The library neither reflects into private fields nor manufactures a domain identity from model data. Repeated references/cycles are preserved within one cloned value, not as a universal alias graph across independently cloned components or overlapping subslices of different lengths. Slice capacity is not preserved. Delivery does not promise a deep copy of every borrowed host object; keep opaque/borrowed values immutable while they are consumed. See [result algebra and migration](migration-task41.md).

## Result cache

The former idempotency middleware is removed. Result caching requires an explicit host `CacheEligibility` predicate evaluated after current authorization on every attempt. Idempotence or ReadOnly alone does not prove that an old answer is reusable. False bypasses partition, store and codec completely; predicate errors fail closed with INTERNAL. The callback receives a defensive prepared snapshot; host closures/ports must be concurrency-safe. A mandatory host partition callback receives prepared context, view, manifest and canonical input. An empty partition fails closed with INTERNAL. The host owns expiry/eviction and binds data revisions, credentials, principal/scope and all relevant dependency freshness to the partition. Eligibility must prove reuse safe even if simultaneous misses dispatch twice; the cache performs no deduplication. The cache key additionally includes manifest/schema, canonical JSON arguments and attachment contents. Cache hits still bind/authorize and never dispatch the handler.

Storage contains an explicitly encoded complete result chunk. The host codec preserves typed values, effects and controls; unsupported values fail explicitly. Cache replay preserves audience, MIME, delivery class and metadata and marks the replay in envelope metadata so host reducers must not apply replayed effects again. Call correlation is rebound to the current call. Exactly one successful result is buffered until producer completion and persistence. Progress is not cached. Business-error terminals pass through unchanged without Put. Producer/consumer/control/cancellation failures never create successful entries. Missing or multiple terminals, storage/codec/limit/configuration failures are INTERNAL and are never input-correctable. Progress may already be delivered; success persistence precedes delivery.

`JSONResultCodec[R,E]` restores declared concrete JSON field types. JSON numbers in dynamic/interface fields (including result, envelope result, effects and metadata) decode as `json.Number`, preserving their numeric lexeme without implicit float64 rounding. This is a JSON representation contract, not reconstruction of arbitrary runtime types inside interfaces; hosts needing exact dynamic Go types or custom serialization semantics supply their own codec. Stored input must contain exactly one complete JSON document; trailing documents or invalid suffixes fail.

The cache is not an operation journal and does not claim atomic duplicate-dispatch protection or exactly-once remote effects. Those guarantees belong to the operation profile. Cache store/codec failures after execution do not authorize retries.

## Activation

An execution profile can be installed on a registry or on a direct-call environment. Built-in tool builders expose the prepared boundary. Wrappers must preserve that capability; unknown/custom tool chains fail closed for a configured registry profile. Middleware remains instrumentation around execution and must not bypass the prepared boundary or manufacture protected cached results.

Registry/view/Session execution starts a new invocation and clears parent-only preparation checks and envelope decorators while preserving the underlying trusted host profile. Same-attempt wrapper/async preparation retains its checks. Built-in tools clone invocation state before preparation; shared host dependencies/session remain shared. Once protected dispatch starts, direct reuse of the handler's inherited environment fails closed before child binding/handler: it is not a scoped nested executor. For a new direct Tool.Execute call supply a fresh invocation-owned RunEnv. Pass the explicitly supplied Registry/view/Session executor for nested calls so current selection, policy and budgets remain enforced.

`testdata/execution/canonical-inputs.json` declares tested representation choices: raw/proxy JSON preserves numeric tokens and missing versus null; typed int64 preserves large integers exactly; a host binder may explicitly normalize missing/null to a default while retaining explicit zero. These are not universal business default rules. `TestCanonicalInputNormativeFixtures` exercises actual builders with exact byte comparisons. `testdata/execution/provider-completion.json` demonstrates a host-owned completion fence: syntactically valid JSON prefixes do not dispatch, explicit completion then parses/validates the full accumulated call. The core parser does not manufacture provider completion.

## Structured stream result

Every NewStreamTool explicitly chooses independent results or a terminal result. Terminal schema compilation and the output limit are fixed at construction; validation state and buffered candidate belong to one invocation. The normative output fixture is `testdata/execution/terminal-schema.json`, exercised by `TestTerminalStreamContract`.

Terminal transitions are empty → candidate → successful producer completion → successful delivery. A second candidate, invalid schema, exhausted limit, producer failure or consumer interruption terminates with a distinct contract error and no successful terminal. Progress may already have been delivered and handler side effects may already have occurred. Pause is a control outcome. Independent streams promise neither terminal cardinality nor implicit aggregation.

## Approval and operation journal contract

`OperationBinding` contains opaque host identity/scope, logical operation ID, tool/schema/view/policy fingerprints and a canonical digest/rules identifier. The host authenticates issuer and provides identity, stable attempt references, trusted time and redacted description from the prepared argument snapshot. Grant issuance is a host-only port. Grant storage and operation claim share one atomic durable boundary.

The library combines the host's opaque argument/dependency binding with prepared canonical JSON and attachment MIME/bytes. Input changes therefore invalidate a grant even when the host dependency identity stays unchanged. Hosts still bind secret reference freshness and non-input dependencies affecting the action; those cannot be inferred from generic arguments.

`OperationStore.Claim` returns either dispatch permission for a new fenced attempt, a previously completed result, an in-progress record or unknown outcome. Expiring an in-progress lease produces uncertainty, never a new dispatch. A changed binding for the same namespace/scope/operation ID is a conflict. Grant expiry, rejection, wrong issuer or mismatch refuses dispatch. Reusing a consumed grant for recovery requires its explicit AllowRecovery policy and a trusted reconciliation/downstream-idempotency decision for the same logical operation.

`Finish` and `Resolve` are compare-and-set operations fenced by binding and attempt. Once handler execution starts, execution/validation/persistence failure without proof of the external result is unknown. Completed bytes contain a full ResultCodec outcome. A later delivery failure does not revert completed execution. Resolution is available only through the trusted host port and requires provenance; proof text supplied by a model is not authority.

Attempt IDs cannot be recycled within a logical operation, even after several reconciled retries: the journal retains all used IDs so a late worker never regains the current fencing identity. The last trusted resolution proof identifier/time remain recorded across the next claim. Infrastructure failures expose `OperationStoreError`, separately from approval/binding decisions and dispatched-handler `OperationOutcomeError`; detailed causes are host diagnostics, not model-facing text.

`Inspect` is a host-only non-mutating read; it never claims/reserves/consumes or advances a lease. Host continuation errors carry a binding/attempt or uncertain record. `ReconcileOperation` reads that binding and calls a trusted host `OperationReconciler` only for unknown or expired-in-progress state. The callback returns evidence, not a target binding: resolution is fenced to the inspected identity/attempt. No handler is dispatched by inspection or reconciliation. Completed outcomes are replayed only through the current authorized execution boundary, not returned as model output by this host port. Callback failure is a distinct `ReconciliationError` and leaves journal state unchanged.

The normative state table is `testdata/execution/operation-transitions.json`. `MemoryOperationStore` implements atomic grant/claim, binding checks, fencing, lease uncertainty and trusted reconciliation. `OperationProfile` buffers one terminal result, persists it before delivery and requests host approval without executing the handler. The host preparation callback must derive a canonical digest (including attachments and secret reference identity) and a redacted description from the same prepared snapshot. Grant issuance and resolution are host-only authority; proof text is provenance, not authentication.

The memory store is not durable. `adapters/execution/filejournal` provides a bounded local durable adapter on Linux/macOS using advisory interprocess locking and file/directory sync. Reopen, concurrent independent handles and subprocess claim tests exercise recovery and claim atomicity. A separate process exits after writing an external-effect receipt but before result persistence; recovery refuses blind dispatch and replays only a trusted reconciled outcome. The state-table fixture is exercised by `TestOperationNormativeTransitions`. `TestOperationTerminalStreamFailureAfterEffectRemainsUnknown` composes the actual terminal builder with the operation profile: invalid/duplicate/aborted terminal after an effect remains unknown and never re-dispatches on repeated delivery. `TestApprovalUsesCanonicalRedactedSnapshotAndSecretFreshness` verifies that redacted UI describes normalized arguments and rotating the host's opaque credential revision invalidates an existing grant. Additional integration coverage and independent final audits remain required; these tests are intermediate evidence, not final acceptance of TLS-001/002.

## Executable result boundary

Built-in builders compile output schemas at construction and validate successful JSON result bytes before a profile can persist them and before delivery, including replay. Validation failure after an action remains uncertain under the operation profile; it never authorizes redispatch. Independent streams validate each JSON result without promising cardinality. Terminal streams additionally retain their producer-completion/cardinality contract. The [result contract](result-contract.md) defines representations, exceptions and clear-break migration.

## Claimed attempt diagnostics

OperationOutcomeError reports an unknown outcome after claim: dispatch may have
occurred. DispatchInvoked records only whether the local profile called its
continuation, without proving an external effect or authorizing claim rollback.
Even context/lease/approval checks failing before invoke leave the claimed attempt
unknown under the existing fenced recovery contract. Typed post-handler contract
errors retain ResultContractError phase/cause and never authorize input repair.
A completed persisted result remains completed after delivery failure.
